AC HRA Portal v28 — Manpower demand / approval workflow
Date: 2026-08-15

本版重點
1. Manpower 需求單與聘用進度分離
   - 線上需求只填需求單位、組別、職位、需求人數、性別／年齡／經驗／學歷條件及需求原因。
   - Recruitment／Join 的已入職資料自動連回需求，顯示已入職／完成、缺口與完成度。
   - Telegram 摘要、核可預覽、核可結果及 Excel 匯出都使用同一套需求／完成口徑。

2. Telegram 核可流程
   - Manpower 的 TG 視窗增加「摘要」與「送群組審查／核可」模式。
   - 審查階段可「確認審查」或「退件」；正式核可階段可逐筆退件或整批退件。
   - 已待核的相同需求不再重發；已核可或已退件的相同穩定需求不再重開批次。
   - 同月份新增其他需求時會建立新批次，不會覆蓋原本已核可的批次。

3. 核可文件
   - 批次完成（核可或退件）會自動生成線上 Sheet、Excel、PDF 連結並附在結果訊息。
   - 若 Workspace 禁止自動設定「知道連結即可檢視」，仍保留已建立的文件連結，並在訊息標示需檢查分享權限，不再誤報整份文件生成失敗。

4. 既有功能保留
   - 中英柬介面與 Telegram 語言切換保留。
   - Cloud merge / incremental sync 及現有 HRA Portal 其他頁面不變。

部署
   - HTML：把本 ZIP 內檔案更新到 GitHub Pages。
   - GAS：把 ga_attendance_cloud.gs 更新到原本的 Apps Script 專案，儲存後建立新版本並重新部署既有 Web App URL。
   - 已有 Webhook、排程及設定時，這次不用再按「一鍵安裝」；只有第一次建立 GAS 專案才需要安裝。
